## ✅ 실기기 파지 1차 성공 (2026-08-25)

전체 파이프라인을 실제로 실행해 빨간 약병 파지에 성공했다:
1. `search_pose`로 파킹(중력 처짐 보정 위해 wrist_flex를 92.31→68.04로
   5도씩 4회 조정, 사용자가 카메라로 보며 확인)
2. `align_and_grasp.py --color red`로 베이스 자동 정렬(249px→19px, 5스텝)
3. 그리퍼 비대칭 구조로 인한 좌우 오프셋을 `base_nudge.py`로 미세 보정

4. `grasp_pose` 직접교시(토크 해제 → 손으로 하강 → 기록)
5. **그리퍼 토크만 해제 → 사람이 손으로 살살 닫음**(서보로 세게 닫으면
   병이 터질 위험이 있어 채택, 닫힌 값 19.15로 확인)
6. 그리퍼 값을 고정한 채(19.15) `home` 프리셋으로 이동 — **병이 그대로
   딸려옴을 카메라로 확인**(사용자 확인: "오 됐다 잘 잡았어")

**남은 것**: 이 전 과정을 스크립트 하나로 자동화(지금은 여러 스크립트를
수동으로 순서대로 실행), 그리퍼 자동 닫기(부하 감지로 세기 조절 필요 —
사람 손처럼 살살 닫는 로직 없음), 다른 색상(파랑/초록)으로도 반복 검증.

## ⚠️ 재현성 결과 — 4회 시행 중 1회만 확실히 성공 (2026-08-25)

전체 과정을 반복 실행한 결과:
1. **1차**: 성공(위 기록). 정렬→왼쪽보정→grasp_pose→그리퍼 19.15 한 번
   닫기→home. 병이 그대로 딸려옴.
2. **2차**: home 도달 후 그리퍼를 두 번 더(19.9→16.3) 추가로 오므렸다가
   **놓침**. 추가 조정이 흔들림을 유발했을 가능성.
3. **3차**: 정렬 자체가 실패(마커 인식 안 됨, `min_area=300`이 실제
   마커 면적 293보다 커서 걸러진 버그 — 150으로 수정), 이후 재시도에서
   목표 좌표가 화면 밖(x=68)으로 튀는 오검출 발생. 사용자가 육안 판단으로
   전/후/좌우 수동 보정 후 진행.
4. **4차**: grasp_pose 도달 후 그리퍼 19.15로 닫았는데 **못 잡음**(사용자
   확인: "지금 못잡았어"). 그 뒤 "그리퍼를 아주 조금 더 닫아야돼"로 18.96까지
   추가 조정했으나 이미 실패한 뒤였음.

**결론**: 지금 파이프라인은 기본 골격은 검증됐지만(2D 정렬 → 직접교시
하강 → 그리퍼 닫기), **베이스 정렬 오차(수 cm급 육안 보정에 의존)와
grasp_pose 하강 시 수평 밀림이 매번 조금씩 달라서 성공률이 낮다**(4회 중
1회). 자동화 스크립트(`align_and_grasp.py`)의 P제어 자체는 픽셀 오차를
잘 줄이지만(수십 px 이내), 그 정밀도가 실제 파지 성공에 필요한 정밀도보다
낮은 것으로 보임 — 그리퍼 유효 파지폭이 좁아서(약병 폭 대비) 몇 mm 오차도
실패로 이어지는 듯.

**다음 우선순위 후보**: ①그리퍼를 부하 감지 기반으로 자동으로 살살
닫는 로직(사람 손 흉내) ②정렬 허용오차(`PIXEL_TOLERANCE`)를 더 타이트하게
②재시도 시 grasp_pose 도달 후 바로 그리퍼를 닫지 말고 카메라로 병이
그리퍼 사이에 실제로 들어와 있는지 최종 확인하는 단계 추가.

## 핵심 아이디어

2·3·4번 모터를 조절해 팔을 "직각 자세"로 만들면, **4번 모터(wrist_flex)와
집게 끝을 잇는 선이 수직**이 된다. 그 수직선의 기준점이 되도록 **4번 모터
몸통에 흰색 스티커**를 붙였다.

따라서:
- 탑뷰 카메라에서 **흰 스티커 = 집게가 실제로 내려갈 지점(x,y)** 의 대리표식
- 약통 바운딩박스 중심과 흰 스티커를 화면에서 겹치면 → 그 순간 집게는 약통
  바로 위에 수직으로 위치
- 이후에는 **높이(z)만 내리고 집게만 닫으면** 잡힌다

이 방식의 이점: 매 프레임 보라색 집게 형상을 추적할 필요 없이, 고대비 흰 점
하나만 검출하면 된다(조명 변화에 강함). 카메라 캘리브레이션/좌표변환 불필요.

## 단계

### 1단계: 직각 자세로 파킹
`data/poses.json`의 `search_pose`로 이동. 2026-08-25 기준 실측값:

| 관절 | 값 |
|---|---|
| arm_shoulder_pan | -3.60 |
| arm_shoulder_lift | 3.16 |
| arm_elbow_flex | 1.98 |
| arm_wrist_flex | 92.31 |
| arm_wrist_roll | -4.35 |
| arm_gripper | 31.56 (열린 상태) |

```bash
./venv/bin/python scripts/goto_saved_pose.py search_pose
```

### 2단계: 흰 스티커 검출
`color_detect.py`의 `white` 범위(저채도 + 고명도)로 검출. 단, 이 자세에서는
화면에 다른 흰색(약통 뚜껑 등)도 잡힐 수 있으므로 구분이 필요하다:
- 후보 중 **검은 모터 위에 있는 원형** 하나만 고르기(주변 명도 대비로 판정)
- 또는 팔이 들어오는 화면 영역(오른쪽 아래)으로 검색범위 제한
- ⚠️ 아직 미구현 — 실제 프레임으로 오탐 여부부터 확인할 것

### 3단계: 베이스 정렬 (폐루프 P제어)
매 프레임:
1. 흰 스티커 중심 `(sx, sy)` 검출
2. 목표 약통 색상 바운딩박스 중심 `(tx, ty)` 검출
3. 오차 `err = (tx - sx, ty - sy)`
4. 오차에 비례해 베이스 속도 명령(x.vel/y.vel), 짧은 펄스로만
5. 오차가 허용치(현재 25px) 안에 들면 정지

부호 매핑(2026-08-25 실측): x.vel 음수(후진) → 팔이 화면에서 오른쪽(+x)으로
이동. 따라서 `x_sign = -1`. y축 부호는 아직 미검증.

구현: `scripts/align_and_grasp.py` (지금은 보라색 집게를 추적하게 되어 있음
→ **흰 스티커 추적으로 교체 필요**)

⚠️ 안전장치(이미 구현됨): 화면 변화가 3스텝 연속 감지 안 되면 자동 정지.
이전에 캐시된 프레임을 읽으며 계속 후진해 벽에 부딪힌 사고가 있었음.

### 4단계: 하강 + 파지
정렬이 끝나면 **비전을 더 이상 안 본다**(look-then-act). 문제는 이 팔이
직교 z축 하강을 지원하지 않는다는 것 — 실제로 내려가려면 2·3·4번 모터가
같이 움직여야 한다.

**해결책: 하강 자세도 직접교시로 기록한다.**
1. 정렬이 끝난 상태에서 토크 해제
2. 손으로 팔을 약통 바로 위, 집게가 물릴 높이까지 내림
3. 그 자세를 `grasp_pose`로 저장(`teach_pose.py grasp_pose`)
4. 이후 실행 시 `search_pose → grasp_pose`로 보간 이동
   (6개 관절이 동시에 부드럽게 움직임 — `goto_saved_pose.py`가 처리)
5. 도달 후 집게 닫기(`--then-close`)

완벽한 직선 하강은 아니지만, 그리퍼 개구폭(실측 12cm) 대비 약통 폭
(3.2×2.3cm)이 훨씬 작아 그 정도 오차는 흡수될 것으로 예상.

### 5단계: 파지 성공 판정 (미구현)
그리퍼 모터의 부하값(Present_Load)으로 물체를 실제로 물었는지 판정.
빈손으로 닫으면 부하가 낮고, 물체를 물면 높다. 실측 기준값 필요.

## 검증해야 할 가정 (아직 확인 안 됨)

1. **흰 스티커가 정말 집게 끝의 수직 위에 있는가** — 직각 자세에서 실제로
   내려봤을 때 스티커가 가리키던 지점에 집게가 도달하는지 확인 필요
2. **하강 중 수평 이동이 얼마나 생기는가** — 2·3·4번이 같이 움직이므로
   집게 끝이 호를 그리며 앞뒤로 밀릴 수 있음. 그 편차가 그리퍼 여유폭
   (약 4cm 이상 여유) 안에 들어오는지
3. **흰 스티커 검출이 약통 뚜껑/반사광과 헷갈리지 않는가**
4. **y축 부호 매핑** — 아직 x축만 실측 확인됨

## 시차(parallax) 보정 — 화면 가장자리 병을 못 집던 문제 (2026-08-26)

### 증상
색상과 무관하게 **화면 가운데 병만** 잡힌다. 파란병 5/5, 초록병 5/5(둘 다
가운데로 옮겨서 시도). 같은 초록병을 왼쪽에 두면 실패 — 로봇이 물체까지
가지 않고 대각선에 멈춘 채 집으려 한다.

### 원인
약병은 바닥에 서 있는 게 아니라 **수직 보드에 걸려 있고**, 고정 USB캠은 그
보드를 정면에서 본다(예전 주석의 "위에서 수직으로 내려다본다"는 틀린 설명).
기준점인 흰 스티커(그리퍼)는 보드보다 카메라 쪽으로 d 만큼 튀어나와 있어
**병과 깊이가 다르다.**

핀홀 투영에서 깊이 (D−d) 인 점의 배율은 f/(D−d), 깊이 D 인 점은 f/D 이므로

    marker_target − c = k · (bottle − c),    k = D / (D − d) > 1

이 보정량은 **화면중심에서 정확히 0이고 가장자리로 갈수록 커진다** — 관측된
"가운데만 성공"과 정확히 일치한다. 보정을 안 하면 목표보다 **덜 가서** 멈춘다.

측정된 프레임(640×480)에서 병 좌표는 blue(169,323) / green(306,302) /
red(466,313). k≈1.21 가정 시 보정량은 blue −29px, green 0px, red +34px 로,
정렬 허용오차(PIXEL_TOLERANCE=25px)를 넘는다 → 실패가 설명된다.

### 확인 과정에서 뒤집힌 가설
처음엔 "마커가 병보다 **높이**가 높아서" 생기는 기복변위로 보고
`k=(H−Z병)/(H−Z마커)` 를 세웠다. 그러나 프레임을 실제로 열어보니 병이 수직
보드에 걸려 있었고, 병 실루엣의 위/아래 끝 무게중심을 뽑아보니 그 변위가
blue(+1.8,−74.1) green(+0.8,−71.4) red(−1.3,−67.0) 로 **화면 전체에서 거의
균일**했다 — 즉 높이차 기복변위로는 좌우 실패를 설명할 수 없었다. 실제 원인은
높이차가 아니라 **깊이차**였다.

### 기준점을 화면중심이 아니라 "잘 되는 병"으로 잡는 이유
목표좌표에는 마커~집게끝 고정 오프셋이 이미 경험적으로 녹아 있다(특히 y는
병 실루엣 아래끝 y2를 쓰고 있어 화면중심과 62px 떨어져 있다). 화면중심을
배율 중심으로 쓰면 그 오프셋을 0으로 가정하는 셈이라, **이미 10/10으로
검증된 가운데 병의 목표까지 y로 13px 밀어버린다**(실측 확인).

`c + k(b−c) + o` 는 `a + k(b−a)`, `a = c − o/(k−1)` 와 완전히 같은 식이므로,
잘 되는 점 하나를 기준점으로 쓰면 미지의 오프셋 o가 정확히 흡수된다.
부수효과로 **그 위치의 동작은 정의상 하나도 안 바뀐다.**

### 구현
- `scripts/parallax.py` — 축별 1차식 `target = a·bottle + b` 저장/적용/피팅.
  **설정 파일이 없으면 항등**이라 캘리브레이션 전까지는 기존 동작 그대로.
- `scripts/calibrate_parallax.py` — 계수 구하는 CLI (아래 사용법).
- `scripts/align_and_grasp.py` — 목표 고정 직후 보정 적용. `--no-parallax` 로 끌 수 있음.
  보정된 목표가 화면 밖이면 `RuntimeError` 로 막는다(계수 과대 방어).
- `config/parallax.json` — 계수(캘리브레이션 시 생성), `config/parallax_samples.json` — 샘플 로그.

### 사용법
방법 1 — 자로 두 번 재기(로봇 없이 가능):

    python scripts/calibrate_parallax.py from-distance \
        --camera-to-board <카메라렌즈~보드 거리> --gripper-offset <보드~흰스티커 거리>

단위는 무관(둘만 같으면 됨). 기준점은 화면중심에 가장 가까운 병으로 자동 선택된다.

방법 2 — 실제 성공 위치로 맞추기(더 정확):

    python scripts/calibrate_parallax.py record --color blue --note "왼쪽"
    python scripts/calibrate_parallax.py record --color red  --note "오른쪽"
    python scripts/calibrate_parallax.py fit

집게가 **실제로 제대로 맞은 순간**에 record 를 실행해야 한다. 축별로 샘플 폭이
60px 미만이거나 기울기가 0.7~3.0을 벗어나면 그 축은 조용히 항등으로 남긴다
(잘못 보정하느니 안 하는 게 낫다).

확인:

    python scripts/calibrate_parallax.py show

### 검증 상태
- 오프라인 단위검증 통과: 항등 기본값 / 알려진 k 복원(잡음 ±4px 포함) /
  샘플 폭 부족·기울기 폭주 거부 / 저장·로드 왕복 / 화면밖 목표 차단.
- **실기기 검증은 아직** — 실제 계수를 재서 넣고 좌·우 병으로 시도해봐야 한다.
